# 用量胶囊：可控续跑方案 V1

日期：2026-10-29。状态：用户已于 2026-10-29 批准继续实施；第一、二批合并为 0.9.0 本地预览版，第三批长期托管保留为后续范围。

## 目标与产品判断

让用户选好允许继续的任务后，可以离开电脑；额度恢复时胶囊在明确授权范围内交接任务，需要用户处理时说明原因，并提供返回原对话的入口。

成功体验是“我知道哪些任务在等、哪个已经交给 Codex、怎样暂停、结果到哪里找”。常驻胶囊继续保持迷你、精致，沿用黑色光泽外壳、深橙色分段灯及已有呼出动效。复杂管理收进展开概览和独立的续跑管理页。

## 现有基础与验证边界

现有 0.8.0 预览版已经支持：按账号选择任务、识别明确的额度中断、额度恢复后的原生队列交接、取消尚未执行的排队指令、持久化记录，以及对不确定提交结果的防重复保护。

现有“逐个提交并等待队列确认”不等于“等待一个任务执行结束才提交下一个”。本方案建议新增后者，以减少多个自动续跑任务同时消耗额度的机会；用户自己启动的其他任务不受胶囊控制。

已验证模拟额度变化后，通过真实 Codex 队列继续一个临时任务，以及真实队列取消。尚未验证真实账号自然耗尽后再恢复额度的完整周期，仍需完成用户实测。该项验证完成前保留预览标识。

## 方案取舍

以下为设计者建议，尚未由用户逐项确认。

| 路线 | 体验及代价 | 建议 |
| --- | --- | --- |
| 可控续跑 | 每个任务默认只恢复一次，有优先级、状态、总暂停和操作记录；范围清楚 | 本次采用的提议 |
| 长期托管 | 多次额度重置后持续恢复；需要时段、次数上限及更完整的运行跟踪 | 后续独立开放 |
| 跨项目调度 | 根据目标安排工作、拆分项目、调整模型；依赖更多能力与授权 | 不进入本轮范围 |

## 一次完整使用流程

1. 用户在续跑管理页搜索并选择任务，查看完整标题、所属项目和授权说明。
2. 默认授权为“下一次因额度中断后，恢复一次”；选择本身不会立即运行任务，也不追溯选择之前的旧中断。
3. 用户可调整优先级，并看到当前是否允许自动续跑。
4. 胶囊确认任务因为额度耗尽而停止，记录“等待额度”。只识别可核实的额度错误，不从自然语言猜测原因。
5. 额度恢复后重新核对账号、授权、最新对话、可用额度和既有交接记录。符合条件才写入原任务队列。
6. 用户在概览看到“已排队”；有可靠执行证据时才显示“正在执行”。
7. 本次续跑结束后停止该次自动授权，展示“本轮已结束”和原对话入口。用户可再次授权。
8. 遇到审批、账号异常或无法确认交接结果时，显示具体原因和可执行的下一步。

## 界面安排

### 常驻胶囊

保留“日额 / 周额”、百分比和五档灯色。日额旁的说明或悬浮提示明确其为五小时窗口。小状态点仅承担提示，悬浮或展开后提供文字，不能只靠颜色传达状态。

- 等待额度：低频呼吸提示。
- 已排队或正在执行：轻微活动指示。
- 需要处理：琥珀色静态提示。
- 自动续跑已暂停：静态暂停标记。

状态动效控制在小区域，不改变胶囊尺寸，并尊重系统减少动态效果设置。

### 展开概览

沿用额度和近七天 Token 小格子，增加一块紧凑的“续跑”摘要：

> 续跑 · 3 项已授权
>
> 1 项等待额度 · 1 项已排队 · 1 项待监测
>
> 优先任务：修复登录页面
>
> [管理任务] [暂停自动续跑]

显示当前阶段最相关的一个主按钮；全局暂停始终容易找到。已暂停时解释“停止新增交接；已经运行的任务请在原对话停止”。额度恢复时间只能标记为预计时间，不承诺到点一定执行。

### 续跑管理页

提供搜索、完整标题提示、项目名、优先级上移/下移、授权范围、状态原因、打开原对话和取消按钮。区分“已授权任务”与“续跑记录”，已结束记录不会冒充仍在运行的任务。

任务详情显示最近一次额度读取时间、等待原因、交接时间和处理建议。读取失败显示“状态暂时无法确认”，保留最近可靠记录及时间。

## 状态与证据

| 显示状态 | 需要的依据 | 用户操作 |
| --- | --- | --- |
| 已授权，待监测 | 当前账号下的明确选择记录 | 取消授权、调整优先级 |
| 等待额度 | 符合现有保守识别规则的额度失败和额度观察记录 | 查看预计恢复时间、取消 |
| 已排队 | Codex 原生队列确认存在本次指令 | 取消排队、打开对话 |
| 正在执行 | 能关联本次指令的真实执行状态 | 打开原对话停止 |
| 需要你处理 | 明确审批状态，或账号、权限、兼容性等异常 | 直达处理入口 |
| 本轮已结束 | 与本次交接匹配的回合结束证据 | 查看回复、再次授权 |
| 交接待核实 | 提交超时或记录冲突，无法确认是否已交接 | 打开对话核实、查看操作指引 |

“回合结束”不等于“整个项目完成”。如果接口无法可靠报告审批或执行状态，显示“已交给 Codex，查看进展”，不用时间经过或队列消失推测正在执行或已经完成。相同原则适用于通知。

## 默认规则与授权边界

- 默认没有新任务被选中；每项任务默认只自动恢复一次。已有选择保留，新增授权规则需清楚展示并由用户启用，不能静默扩大授权。
- 优先级由用户排序；同一优先级按授权时间排序。
- 默认一次只放行一项自动续跑，上一项有可靠的本轮结束证据后再考虑下一项。状态不明时暂停后续自动交接并解释原因。遇到等待审批的任务，用户可选择暂时跳过并放行下一项，胶囊不自行越过。
- 每次派发前确认五小时和周额度都有余量，默认暂不额外扣留额度。可选“保留手动使用额度”，对两个窗口分别设置阈值，并根据新读数停止新增派发。
- 保留阈值不能保证额度不会跌破，也不能精确限制单项任务消耗；已运行任务及其他客户端仍可能继续用量。
- 用户主动停止、等待确认、网络失败和普通代码错误，不属于额度恢复续跑的触发条件。
- 用户在原对话发起新一轮或改变任务后，旧的恢复机会失效，重新观察后续明确的额度中断。
- 账号改变或退出登录时暂停原账号授权；登录恢复后重新核对。休眠或退出期间不执行监测，唤醒后必须校验真实状态。
- 不自动使用重置卡。每次使用都由用户明确确认，任何续跑开关都不能替代这次确认。
- 所有执行延续 Codex 原任务的权限和审批设置；胶囊不替用户审批。

“只恢复一次”指一个额度中断对应的一次可确认交接。提交结果不明也会占用该次待核实机会，不能通过重试再次发送。取消且已确认尚未执行后，授权进入取消状态；需要再次选中才会重新等待。

## 暂停、取消和停止

| 操作 | 明确效果 |
| --- | --- |
| 暂停自动续跑 | 阻止所有新增交接，保留任务选择和顺序；既有排队及运行状态继续显示 |
| 取消某项授权 | 停止该项监测，并尝试撤回仍在排队的胶囊指令 |
| 取消所有等待项 | 逐项撤回尚未执行的胶囊指令；失败或不确定项继续保留并说明 |
| 停止正在执行的任务 | 本轮提供打开原对话的明确入口，由用户在 Codex 停止 |

取消与 Codex 接手可能同时发生。撤回失败时必须显示“可能已开始，请在原对话查看”，不能显示取消成功。恢复总开关前展示仍在队列或待核实的记录，先协调状态再考虑新交接。

## 通知与结果

首次提供系统通知的启用入口；未获授权时在面板内提示即可。默认只通知本轮结束、可靠识别到必须处理的事项及实质失败，同一事件只通知一次。普通刷新、等待和重复故障不反复打扰。

初版结果卡只展示真实回合状态、时间、项目及对话入口；可安全提取时展示最终回复的短摘录。结果文本作为普通文本展示，不执行其中的命令或链接。

不为结果卡额外调用模型。若以后增加 AI 摘要，单独说明并由用户开启；实际任务续跑本身仍会消耗额度。轮询与本地状态整理不消耗模型 Token。

## 实现约束

复用现有原生任务队列、账号绑定和持久化交接账本。客户端消息 ID 仅用来关联记录，不能视为服务器去重键；未确认的入队操作不自动重发。清除界面记录不能抹去防重放所需的底层标记。

按需读取已授权任务，避免高频读取所有历史记录。搜索优先检索已加载列表，保留“加载更多”并清楚提示范围；完整历史搜索需先验证接口支持，不能让用户误以为未加载任务不存在。

核心触及：AutoResume.swift 的授权与规则、AutoResumeService.swift 的调度及状态核对、HandoffLedger.swift 的持久化、ResumeSettingsView.swift 和 Views.swift 的界面，以及四种现有语言的文案。通知为独立模块，系统权限失败不能影响核心队列。

## 交付顺序

第一批：准确状态、搜索和标题、优先级、默认一次授权、总暂停、取消反馈、原对话入口。先把用户看得懂、管得住做完整。此阶段若尚无可靠的执行结束跟踪，每次只自动交接一项，随后暂停放行；用户在原对话核实后，可明确点击“放行下一项”。该动作只授权下一项，不重发上一项，不把上一项标记为项目完成。不能以依次收到入队确认替代执行结束。

第二批：可靠运行跟踪、等待本轮结束再派发下一项、通知和结果卡、可选额度保留阈值。仅在真实接口能提供足够证据时启用对应状态。

第三批：独立开启的长期托管。新增允许运行的时段、恢复次数上限和暂停原因；跨夜时段、时区变化、额度再次耗尽都需要明确规则及验证。本批不自动随前两批开放。

## 验收标准

1. 无选择时不提交；选择之前的旧失败不被续跑；非额度原因不触发。
2. 一次授权最多对应一次交接；连续刷新、重启、多个胶囊实例和超时都不产生重复续跑。
3. 两项已授权任务按顺序放行：第一批在一次交接后等待用户明确放行下一项；第二批具备可靠结束跟踪后才自动放行下一项。上一项状态不明或等待处理时，下一项不会擅自开始。
4. 总暂停后不再新增交接；排队取消成功有证据，取消竞态不会假报成功。
5. 未知额度、切换账号、过期登录、过时数据、任务已改变时均给出可理解的原因。
6. 正在执行、本轮结束和需要审批都有可靠依据；无法核实时明确显示未知。
7. 通知拒绝授权也能使用；同一事件不重复通知；概览、队列和原对话入口状态一致。
8. 完成真实自然额度重置周期实测，记录准确的等待、恢复与交接结果，再决定是否移除预览标识。

本轮只产出方案，不修改运行中的胶囊、不改变现有任务选择、不发送续跑指令，也不使用重置卡。
